`DataTable` is the fluent API used to configure table options, columns, extensions, and loading mode.

## Constructor

```php
new DataTable(
    id: 'users',
    options: [],
    attributes: [],
    extensions: [],
)
```

```php
use Pentiminax\UX\DataTables\Enum\Icon;
use Pentiminax\UX\DataTables\Model\DataTable;
use Symfony\Component\Routing\Generator\UrlGeneratorInterface;

$table = (new DataTable('orders'))
    ->emptyState('No orders yet', 'Orders appear here once customers check out.', Icon::Inbox, [
        'label' => 'Create an order',
        'url'   => '/orders/new',
    ])
    ->rowClass(static fn (Order $order): ?string => $order->isOverdue() ? 'table-danger' : null)
    ->recordUrl(fn (Order $order): string => $this->urlGenerator->generate('order_show', ['id' => $order->getId()]));
```

See [Row Presentation](/features/row-presentation/) for behavior, accessibility, and security notes.

## Public API

The methods documented here are the supported configuration surface. A few public methods exist only
because the runtime calls them while preparing a render, such as `setPreparedFilterLabels()`,
`markTemplateColumnsRendered()`, or `setDataTableClass()`. They carry an `@internal` tag in their
PHPDoc and are excluded from the backward-compatibility promise: do not call them from your tables,
because they can change or move in any release.

## Example

```php
use Pentiminax\UX\DataTables\Enum\Feature;
use Pentiminax\UX\DataTables\Enum\Language;
use Pentiminax\UX\DataTables\Model\DataTable;

$table = (new DataTable('users'))
    ->serverSide(true)
    ->processing(true)
    ->language(Language::EN)
    ->layout([
        'topStart'    => Feature::PAGE_LENGTH,
        'topEnd'      => Feature::SEARCH,
        'bottomStart' => Feature::INFO,
        'bottomEnd'   => Feature::PAGING,
    ]);
```
