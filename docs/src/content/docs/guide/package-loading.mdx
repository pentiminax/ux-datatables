The bundle does not ship or maintain the DataTables.net packages. Your application owns a small
amount of copied frontend code, written by `ux-datatables:install`: the **package loaders** for
your kit and extensions and, for Bootstrap 5, the modal adapter. Everything that carries a security
boundary or the payload contract (the PHP runtime, the Ajax controllers, the `datatable` Stimulus
controller, the Twig templates, the `<dialog>` modal adapter and the Tailwind theme stylesheet)
stays in the Composer package and receives fixes through `composer update`.

The `datatable` controller imports nothing but `@hotwired/stimulus`. You install and resolve only
the packages you register, and a package you do not register is never requested.

<Aside type="note" title="Stable for the whole 2.x line">
  The loader signature, the `packageLoaders`, `modalAdapters` and `columnStyleAdapters` registries,
  and the modal and column style adapter interfaces are covered by the backward compatibility
  promise for 2.x. Copied code never has to be regenerated to stay supported.
</Aside>

## Run the install command

```bash
php bin/console ux-datatables:install --style=tailwind buttons responsive select
```

Extensions are arguments: `buttons`, `colReorder`, `columnControl`, `fixedColumns`, `fixedHeader`,
`keyTable`, `responsive`, `rowGroup`, `scroller`, `searchBuilder` and `select`. Pass none to pick
them interactively, or `--all` to select every one. Without arguments the command also scans your
`AbstractDataTable` classes for the extensions they use (`--no-detect` skips the scan).

<Tabs>
  <TabItem label="AssetMapper">
    The command runs `importmap:require` for the packages you need. It pins a stylesheet to the
    version of its package and never downgrades a pin.

    ```bash
    php bin/console ux-datatables:install --style=tailwind buttons responsive select
    php bin/console cache:clear
    ```
  </TabItem>
  <TabItem label="Webpack Encore">
    The command cannot tell npm, yarn, pnpm and bun apart, so it prints the install line instead:

    ```bash
    php bin/console ux-datatables:install --style=tailwind buttons responsive select
    # Run the install line the command prints, for example:
    npm install datatables.net-dt@3.1.3 datatables.net-buttons-dt@4.1.2 ...
    npm run watch
    ```
  </TabItem>
</Tabs>

For `buttons`, the command also registers JSZip and pdfmake. They load only when a table has an
`excel` or `pdf` button. Lucide is always registered, because icon columns and empty states use it
and the command cannot detect them.

### Running it again

- An unchanged file is left alone.
- A loader file the command generated and you did not edit is regenerated. It keeps the extensions
  it already loads, so running the command with one more extension adds only that loader. This also
  migrates the files written by the 1.5 and 1.6 installer.
- A file you edited is shown as a diff and replaced only after you confirm. A non-interactive run
  never overwrites it and says which files it kept.
- Without `--style`, the kit of the existing `assets/datatables.js` is kept.

### Two styles in one application

`styleFramework()` selects the style per table. When one application mixes styles (for example a
Bootstrap 5 admin and a Tailwind public site), register the loaders of each style under its
framework, as the third argument of `register()`. A loader registered for a framework wins over the
one registered for the name alone:

```js
import { packageLoaders } from '@pentiminax/ux-datatables/dist/core.js'

packageLoaders
    .register('dataTables', () => import('datatables.net-dt'), 'dt')
    .register('dataTables', () => import('datatables.net-bs5'), 'bs5')
```

A table that requests a style with no registered adapter fails with a message naming the missing
registration.

## Manual setup

You do not need the command. Three files carry the whole setup.

<Steps>

1. **Select the style in `config/packages/data_tables.yaml`**

    ```yaml
    data_tables:
        style_framework: dt # dt | bs5
    ```

2. **Enable `datatable` in `assets/controllers.json`**

    ```json
    {
        "controllers": {
            "@pentiminax/ux-datatables": {
                "datatable": {
                    "enabled": true,
                    "fetch": "eager",
                    "autoimport": {
                        "@pentiminax/ux-datatables/dist/styles/datatables-base-style.css": true,
                        "@pentiminax/ux-datatables/dist/styles/datatables-tailwind-theme.css": true,
                        "datatables.net-dt/css/dataTables.dataTables.min.css": true,
                        "datatables.net-bs5/css/dataTables.bootstrap5.min.css": false
                    }
                }
            }
        },
        "entrypoints": []
    }
    ```

3. **Register the packages in `assets/datatables.js`**

    Import it first from `assets/stimulus_bootstrap.js` (or `assets/bootstrap.js`), before
    `startStimulusApp()`:

    ```js
    import './datatables.js'
    import { startStimulusApp } from '@symfony/stimulus-bundle'

    startStimulusApp()
    ```

    ```js
    import { packageLoaders } from '@pentiminax/ux-datatables/dist/core.js'

    packageLoaders
        .register('dataTables', () => import('datatables.net-dt'))
        .register('select', () =>
            Promise.all([
                import('datatables.net-select-dt'),
                import('datatables.net-select-dt/css/select.dataTables.min.css'),
            ]))
    ```

</Steps>

A loader imports both the JavaScript and the stylesheet its package needs, and you choose the
style by choosing the package (`datatables.net-select-bs5` instead of `-dt`). Two packages need an
extra import: `searchBuilder` must import `datatables.net-datetime` first, and `pdfmake` must
import `pdfmake/build/vfs_fonts.js`.

With AssetMapper, add the `dist/core.js` entry and install the packages:

```bash
php bin/console importmap:require @pentiminax/ux-datatables/dist/core.js \
    --path=@pentiminax/ux-datatables/core.js
php bin/console importmap:require datatables.net-dt datatables.net-select-dt \
    datatables.net-dt/css/dataTables.dataTables.min.css \
    datatables.net-select-dt/css/select.dataTables.min.css
```

With Encore, run `npm install` for the same packages.

The package's main entry, `@pentiminax/ux-datatables`, is the same core entry: it exports the
controller, `packageLoaders`, `buttonActions`, `modalAdapters` and the adapter types.

## The "package is not registered" error

A table that needs a package you did not register fails with:

```text
The "select" package is not registered. Install it and register it with packageLoaders.register('select', loader).
```

The package name is the first argument of `register()`. Fix it by running the install command with
the missing extension added to the list, or by adding the `register()` call to
`assets/datatables.js` by hand. A table that enables an extension through its PHP model (`select()`,
`responsive()`, `buttons()`) needs that extension registered.

JSZip, pdfmake and Lucide are optional and never raise this error. Without JSZip or pdfmake,
Buttons loads without Excel and PDF support, and the console warns which package is missing for the
`excel` or `pdf` button your layout declares. A JSZip or pdfmake that fails to load disables only
its button and warns. Without Lucide, tables initialize without their icons and the console warns.

## Leftover 1.x configuration

`data_tables.package_loading: registered` is accepted, ignored and deprecated: remove it.
`package_loading: builtin` fails, because the built-in loaders no longer exist; run
`ux-datatables:install` instead. The `datatable_core` controller stays as a deprecated alias of
`datatable` until 3.0.

## Third-party extensions

Registering an extension the bundle does not know is not supported. `packageLoaders.register()`
throws for a name outside this closed list: `dataTables`, `buttons`, `jszip`, `pdfmake`, `bootstrap`, `lucide`,
`colReorder`, `columnControl`, `fixedColumns`, `fixedHeader`, `keyTable`, `responsive`, `rowGroup`,
`scroller`, `searchBuilder` and `select`.
